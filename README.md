# IT STEP — електронна бібліотека

Закрита Django-бібліотека для коледжу та університету: дисципліни, книги й ZIP-архіви курсових та дипломних робіт. Облікові записи створює тільки адміністратор; публічної реєстрації немає.

## Запуск

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate
# Linux: source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
python manage.py migrate
python manage.py createsuperuser
python manage.py runserver
```

Шляхи: `/` — вхід; `/catalog/` — бібліотека; `/repository/` — ZIP-архіви; `/teacher/` — кабінет викладача; `/admin/` — адміністрування (лише суперкористувачі). Імпорт студентів: Admin → Профілі студентів → Імпортувати студентів (CSV). Поля: `username,first_name,last_name,institution_slug`.

**Безпека:** перед публікацією налаштуйте секретний ключ, HTTPS, домен, резервні копії, належні права на навчальну літературу і архіви. `.env`, `db.sqlite3`, приватні файли й паролі не завантажувати в GitHub.

## Оновлення сервера

```bash
git pull --ff-only origin main
pip install -r requirements.txt
python manage.py migrate
python manage.py collectstatic --noinput
# далі перезапуск вебсервісу
```


## Ролі, додавання матеріалів і статистика

- **Адміністратор / директор** — лише облікові записи з `is_superuser=True` можуть відкрити `/admin/`. Можуть створювати користувачів, заклади, дисципліни, профілі викладачів і студентів, переглядати й додавати книги, приховувати публікації та переглядати аудит.
- **Викладач** — звичайний активний користувач (`is_staff=False`, `is_superuser=False`) із `TeacherProfile`. Адміністратор створює його в «Користувачі», а потім додає «Профіль викладача» та призначає дисципліни. У `/teacher/` викладач бачить лише свої матеріали; через `/teacher/books/add/` він може завантажити книгу тільки до призначених активних дисциплін. Нові матеріали **публікуються одразу**, але адміністратор може приховати їх прапорцем `is_published`. Викладач може редагувати тільки власні книги, поки дисципліна залишається призначеною.
- **Студент** — звичайний користувач зі `StudentProfile` та дозволеними закладами. Не має доступу до `/admin/` і до редагування матеріалів. CSV-імпорт студентів залишено без змін.

### Облік завантаженої літератури

У «Книги» відображається `Хто додав`; дані зберігаються у `Book.uploaded_by`. У «Історія змін літератури» зберігаються дата, користувач, назва дисципліни, додавання, редагування і видалення. Книги, що існували **до цього оновлення**, матимуть порожнє поле `Хто додав`: історичне авторство не можна відновити автоматично.

### Активність студентів

У «Профілі студентів» адмін бачить кількість успішних входів, останній вхід, кількість переглядів сторінок та запитів на завантаження. «Історія» відкриває журнал саме цього студента. Розділ «Активність студентів» дозволяє фільтрувати за діями та часом, шукати користувача/назву матеріалу. Фіксуються:

- успішний вхід до Django (не зовнішня Basic Auth);
- відкриття каталогу та дисципліни;
- відкриття репозиторію робіт;
- **запити** на завантаження книг та ZIP (не доказ прочитання/завершеного завантаження).

Події починають збиратися тільки **після встановлення оновлення**. Історичні входи не відновлюються. У журналі немає IP-адрес, паролів, User-Agent, пошукових запитів або вмісту файлів. У кабінеті студента є повідомлення про облік активності. Організація має визначити строки зберігання, поінформувати користувачів та обмежити доступ відповідно до власної політики захисту даних.

Для контролю строку зберігання:

```bash
python manage.py prune_activity --days 365 --dry-run
python manage.py prune_activity --days 365
```

Другу команду запускайте лише після узгодження строку зберігання. За потреби додайте запуск до системного планувальника.

### Безпечне оновлення працюючого сервера

Перед оновленням збережіть базу `db.sqlite3` **узгодженим бекапом SQLite** (Python `sqlite3.Connection.backup`) та окремо каталог `private_uploads/`. Не розміщуйте резервні копії у публічному Git-репозиторії. Ніколи не видаляйте базу та приватні файли при деплої.

Після резервного копіювання, коли зміни опиняться у `main`:

```bash
cd /srv/itstep-library
source .venv/bin/activate
git status --short
git pull --ff-only origin main
python -m pip install -r requirements.txt
python manage.py migrate
python manage.py collectstatic --noinput
python manage.py check
sudo systemctl restart itstep-library
sudo systemctl status itstep-library --no-pager
```

Зміни моделей вносяться міграцією `library.0003_teacher_activity` без видалення чинних користувачів, дисциплін або книг. Встановлені на зовнішньому reverse proxy HTTPS та HTTP Basic Auth зберігаються й налаштовуються окремо від Django.

Автотести: `python manage.py test` та `python manage.py makemigrations --check --dry-run`.
