# Публічна сторінка привітання
Це опційна зміна Nginx. Django, база даних і чинні облікові записи зберігаються.
- `/`: статична сторінка, яку Nginx віддає без авторизації.
- `/accounts/login/`: чинна сторінка Django, перед якою Nginx запитує HTTP Basic Auth.
- Форма персонального входу надсилає POST до `/accounts/login/`, а не до публічного кореня.
- Інші маршрути залишаються без змін.

## Встановлення
1. Перевірте поточний конфіг через sudo nginx -T (не публікуйте секрети). Зробіть резервну копію конфігурації Nginx та даних бібліотеки.
2. Отримайте гілку feature/public-welcome-page у /srv/itstep-library без перезапису локальних змін. Перевірте права читання index.html користувачем Nginx.
3. Переконайтеся, що auth_basic та auth_basic_user_file діють у всьому HTTPS server block і що жоден захищений location не вимикає їх. Якщо Basic Auth налаштовано лише на зовнішньому проксі, застосуйте виняток саме там або узгодьте його з адміністратором проксі.
4. Додайте в чинний HTTPS server block include /srv/itstep-library/deploy/welcome/nginx-location.conf; (або інтегруйте точний location вручну). Не замінюйте весь server block. Якщо там вже є location = /, адаптуйте його; не створюйте дубль. Збережіть чинні security headers, зокрема HSTS: add_header у вкладеному location може скасувати успадкування заголовків. За потреби перенесіть чинні заголовки до нового location.
5. Виконайте python manage.py check і python manage.py test, перезапустіть сервіс Django, щоб він завантажив змінений шаблон.
6. sudo nginx -t && sudo systemctl reload nginx.

## Перевірка до введення в експлуатацію
З чистого браузера/без Authorization і cookies: GET / повинен давати 200 і лише публічну сторінку. GET /accounts/login/, /catalog/, /repository/, /teacher/, /admin/, /books/1/download/, /repository/1/download/ повинні давати 401 з WWW-Authenticate: Basic. Перевірте також статичні та приватні файли, прямий доступ до upstream (не має бути доступний з інтернету), альтернативні домени та HTTP (має перенаправляти на HTTPS). Не допускайте доступу до приватних завантажень напряму через Nginx.
Після успішного Basic Auth перевірте форму Django, неправильний пароль, персональний вхід, ролі, вихід і повернення до входу. Не вводьте паролі у командний рядок чи репозиторій.
Якщо перевірка не пройдена, відновіть попередній конфіг Nginx і попередню версію шаблону, перевірте nginx -t та перезавантажте конфіг.
Нових міграцій немає. Реальна конфігурація Nginx не зберігається у репозиторії, тому цей приклад потребує перевірки на сервері.
